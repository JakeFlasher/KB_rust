# Rust Port — Current-State Audit (CACG)

**Status:** audit, evidence-based.
**Date:** 2026-05-23.
**Audited tree:** `master` @ `7a0ad43` (`Round 15: fix Round-14 code-review findings (P2 BM25 zero-token corpus)`).
**Author:** senior-architect audit pass. Feeds the next-phase planning decision.

This document is a rigorous, code-verified inventory of the CACG Rust port. It was
produced by reading the workspace source, the `.humanize/plans/` files, the `.humanize/rlcr/`
loop states, the parity harness, and the git history — and by running the test
suite and every static gate locally. **Where the project memory or a plan's stated
precondition disagrees with the code, the code wins and the discrepancy is flagged.**

Headline findings, stated up front so the rest of the document can be read as
evidence:

1. **M5 (retrieval foundation) is COMPLETE and FINALIZED.** The RLCR loop
   `.humanize/rlcr/2026-05-22_17-29-31/` ran Rounds 0–15, all 17 tasks
   (`task-rf-1` … `task-rf-17`) and all six acceptance criteria (AC-1 … AC-6) are
   recorded complete-and-verified, and a Finalize Phase ran. The tree is green.
2. **The M5 plan's stated precondition is FALSE.** The M5 plan asserts the M3
   verify-hot-path phase "`task-vh-18` through `task-vh-28` is complete: `kb verify
   --round-summary`, the M3 instruction-count perf gate, and the CFA first-bite
   migration … have all landed." **None of those landed.** The M3-verify loop was
   *stopped* (not finalized) at Round 26 after `task-vh-17`. M5 was planned and
   executed on a precondition that never held. This is the single most important
   discrepancy in this audit (see §3, §8, §9).
3. **5 of 14 `kb` verbs are native; 9 still dispatch to the unimplemented stub.**
4. **`cacg-ingest` and `cacg-semantic` are placeholder crates** — one stub function
   each, ~29 / ~26 LoC. M4 (Pdfium ingest) and Layer-3 semantic verification are
   entirely unstarted in Rust.

### 2.1 `kb verify` is native but PARTIAL — two declared scoped omissions

`dispatch_verify` (`main.rs:211-282`) delegates the single-card path to
`cacg_core::verify::verify_one_card`. But two branches are not implemented
(`main.rs:208-215`, doc-comment + code):

- `--round-summary <PATH>` → `eprintln!("CACG-CLI-002: kb verify --round-summary
  not yet implemented")`, exit 1. The round-summary driver was M3-verify task-vh-20,
  which never landed (see §3, §9b).
- `--semantic` / `--semantic-judge` — the clap flags exist (`lib.rs:219-224`,
  `verify_semantic` mutex group) but `dispatch_verify` never constructs a Layer-3
  `SemanticSpec`. Layer-3 is unstarted (`cacg-semantic` is a stub, §1.5).

So `kb verify <card>` is fully native and parity-gated; `kb verify --round-summary`
and `kb verify --semantic*` are not.

`--source-matrix` is clap-`required = true` on `lint`, `verify`, `search`, `show`
(`lib.rs:177-178, 230-231, 319-320, 351-352`) — matching the trust kernel's
evidence-required policy. A missing flag exits 2 (clap usage error).
